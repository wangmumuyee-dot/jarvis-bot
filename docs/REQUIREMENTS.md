# 个人 Jarvis 机器人需求清单

## 1. 项目背景

用户希望实现一个以飞书为入口的个人机器人。用户可以通过自然语言给机器人发送消息，让机器人帮助完成记账、待办、提醒、链接或文本总结、Obsidian 知识库沉淀等工作。

这个项目的核心不是做一个普通聊天机器人，而是建立一个个人信息输入中枢：

- 把零散消费记录沉淀成结构化账本
- 把临时想法和待办转化为可提醒、可追踪的任务
- 把文章、链接、文本沉淀到 Obsidian 知识库
- 通过飞书私聊形成一个低摩擦、高频可用的个人 Jarvis

## 2. 总体目标

在 7 天内完成一个可真实试用的 MVP：

- 飞书应用机器人私聊可用
- Python FastAPI 接收消息并回复
- SQLite 作为唯一真实数据源
- 通用 LLM API 负责自然语言理解和摘要生成，默认使用 OpenAI-compatible Responses API
- Obsidian Markdown 作为知识库输出
- 旧笔记本作为第一版服务端
- 代码结构按未来云部署设计

MVP 完成后，用户应能连续 7 天通过飞书使用机器人，并验证记账、待办、提醒、知识库写入等核心场景。

## 3. 已确认决策

| 领域 | 决策 |
| --- | --- |
| 聊天入口 | 第一版只支持飞书机器人私聊 |
| 使用对象 | 第一版只服务用户本人 |
| 部署方式 | 第一版使用旧笔记本常驻运行 |
| 后续迁移 | 代码和配置按未来云部署设计 |
| 主数据源 | SQLite 是唯一真实数据源 |
| Excel | 作为导出和备份，不作为主数据源 |
| Obsidian | 作为知识库和 Markdown 沉淀，不作为结构化状态源 |
| AI API | 使用通用 LLM 配置，可接 OpenAI-compatible 厂商 |
| 高敏信息 | 密码、身份证、银行卡等不得发送给 AI |
| 提醒可靠性 | 普通提醒由机器人负责，关键提醒需要备用机制 |
| MVP 节奏 | 7 天内完成第一个可试用版本 |

## 4. 用户角色

### 4.1 主用户

用户本人。

需求特点：

- 希望通过飞书快速输入
- 不想频繁打开多个工具
- 希望机器人能理解自然语言
- 希望短期看到正反馈
- 希望长期演化为个人系统
- 对提醒可靠性要求较高
- 接受使用大模型 API，但要求安全边界

### 4.2 非目标用户

第一版不支持：

- 多用户
- 家庭成员协作
- 团队协作
- 群聊多人触发
- 多 agent 协作

## 5. 功能需求

### 5.1 飞书私聊入口

#### 需求

- 用户可以在飞书中与机器人私聊
- 机器人能接收文本消息
- 机器人能回复处理结果
- 机器人只响应白名单用户
- 机器人忽略群聊事件和非授权用户

#### 示例

用户：

```text
今天午饭 38
```

机器人：

```text
已记录支出：38 元，分类：餐饮，备注：午饭，时间：今天。
```

#### 验收标准

- 飞书机器人能稳定接收私聊文本消息
- 机器人能主动回复私聊消息
- 非白名单用户消息不会被处理
- 重复事件不会重复入库

### 5.2 意图识别

#### 需求

机器人需要识别用户消息属于哪类操作：

- 记账
- 创建待办
- 创建提醒
- 查询账本
- 查询待办
- 文本总结入库
- 链接总结入库
- 修改最近记录
- 完成待办
- 未知意图，需要反问

#### 设计要求

- 使用 LLM API 输出结构化 JSON
- 高敏信息检测必须发生在调用 LLM 之前
- 无法确定时机器人必须反问，而不是乱猜
- 保留原始输入的必要摘要或脱敏版本，便于调试

#### 验收标准

- 使用 30 条真实输入测试
- 至少 27 条意图分类正确
- 对不确定内容可以反问用户
- 输出 JSON 能通过 schema 校验

### 5.3 记账流水

#### 需求

第一版支持极简账本，但保留常见流水类型：

- 支出 expense
- 收入 income
- 退款 refund
- 转账 transfer
- 报销 reimbursement

第一版不做：

- 多账户余额
- 信用卡账单管理
- 资产负债表
- 自动冲销原订单
- 完整报销审批
- 专业财务核算

#### 支持输入示例

```text
今天午饭 38
打车 26
买书花了 89
工资到账 12000
昨天买鞋退款 199
给小王转账 200
打车 48，待报销
打车报销到账 48
```

#### 数据要求

账本流水至少记录：

- 类型
- 金额
- 币种
- 分类
- 备注
- 发生时间
- 是否待报销
- 报销状态
- 原始输入
- 创建时间

#### 查询需求

第一版支持简单查询：

```text
这个月餐饮花了多少？
今天花了多少钱？
本月收入多少？
有哪些待报销？
```

#### 导出需求

- 支持将账本流水导出为 Excel
- Excel 来自 SQLite，不进行反向同步
- Excel 作为查看、备份和筛选用途

#### 验收标准

- 能新增常见账本流水
- 能查询本月、本日、分类汇总
- 能导出 Excel
- 退款、转账、报销作为流水事件被记录

### 5.4 待办和提醒

#### 需求

第一版支持：

- 无时间待办
- 一次性定时提醒
- 简单重复提醒
- 普通提醒和关键提醒分级
- 完成待办
- 查询今日待办

第一版不支持：

- 项目任务
- 子任务
- 看板
- 多人任务协作
- 复杂重复规则
- 节假日排除
- 高级日历调度

#### 支持输入示例

```text
记一下：买空气炸锅
明天下午 3 点提醒我交房租
下周五晚上 8 点提醒我买礼物
每天早上 9 点提醒我看计划
每周一上午 10 点提醒我写周报
```

#### 提醒可靠性要求

- 提醒必须写入 SQLite
- 定时任务扫描待提醒记录
- 到点通过飞书主动提醒用户
- 发送失败需要重试
- 发送结果需要记录状态
- 关键提醒需要备用机制

#### 普通提醒和关键提醒

普通提醒：

- 由机器人负责提醒
- 适合一般待办

关键提醒：

- 机器人提醒
- 需要提示用户创建备用提醒
- 可扩展为飞书日历或手机日历同步

#### 验收标准

- 一次性提醒可以到点触发
- 简单重复提醒可以生成下一次提醒
- 连续试用 7 天无漏发
- 失败记录可追踪
- 用户可以完成待办

### 5.5 Obsidian 知识库

#### 需求

机器人需要将文本或链接总结为 Obsidian Markdown 笔记，并按 PARA 风格组织知识库。

第一版目录结构：

```text
00_Inbox/
01_Projects/
02_Areas/
03_Resources/
04_Archive/
```

建议初始子目录：

```text
01_Projects/
  个人机器人/

02_Areas/
  AI/
  个人成长/
  健康/
  财务/
  工作/

03_Resources/
  文章/
  工具/
  书籍/
  教程/
```

#### 写入规则

- 明确属于当前推进目标的内容写入 `01_Projects`
- 长期维护领域写入 `02_Areas`
- 外部资料、文章、教程、书籍写入 `03_Resources`
- 分类不确定时写入 `00_Inbox` 并向用户确认
- 第一版不自动移动、删除、合并已有笔记
- 第一版不自动重构全库

#### 笔记模板

```markdown
---
type:
source_type:
source_url:
created_at:
tags:
related:
---

# 标题

## 摘要

## 核心要点

## 和我的关系

## 可行动项

## 原始来源
```

#### 支持输入示例

```text
帮我总结这段话，并放进知识库：...
总结这个链接 https://example.com
这篇文章和我的个人机器人项目有关，帮我整理一下
```

#### 验收标准

- 能生成合法 Markdown 文件
- 能写入 Obsidian vault
- 能生成标题、摘要、要点、标签和来源
- 能按 PARA 目录进行受控写入
- 不确定分类时会反问

### 5.6 链接总结

#### 需求

- 用户发送链接后，机器人抓取网页正文
- 提取标题、正文、来源 URL
- 调用 LLM API 总结
- 写入 Obsidian Markdown

#### 第一版限制

- 只支持公开网页
- 不支持需要登录的网站
- 不保证所有网页都能抓取成功
- 抓取失败时给出明确反馈

#### 验收标准

- 常见公开网页可以抓取并总结
- 失败时不会静默失败
- 输出笔记保留原文链接

### 5.7 Excel 导出

#### 需求

- 支持导出账本流水到 Excel
- 第一版可以手动触发导出
- 后续可扩展为每日或每周自动导出

#### 示例

```text
导出本月账单
导出全部账本
```

#### 验收标准

- Excel 文件能打开
- 字段完整
- 金额、日期、分类正确

### 5.8 安全和隐私

#### 必须支持

- 只响应用户本人飞书 user_id
- 只处理机器人私聊
- 飞书 webhook 校验
- LLM API key 放在 `.env`
- 飞书密钥放在 `.env`
- 日志不记录密钥
- 日志默认不记录完整敏感原文
- 调用 LLM 前进行本地敏感信息检测

#### 禁止发送给 AI 的内容

- 密码
- 身份证号
- 银行卡号
- CVV
- 短信验证码
- API key
- 私钥
- 助记词
- 其他明显高敏凭证

#### 命中高敏信息时

机器人应拒绝处理，并回复：

```text
我检测到这条消息可能包含身份证、银行卡、密码或密钥等敏感信息。
为保护隐私，我不会发送给 AI，也不会保存原文。
请删除敏感信息后重新发送。
```

#### 第一版不做

- 端到端加密
- 多用户权限管理
- 本地大模型私有化
- 安全审计后台

## 6. 非功能需求

### 6.1 可靠性

- 旧笔记本不断电、不休眠、网络正常时提醒不漏发
- 提醒失败需要重试
- 关键任务需要备用提醒机制
- 机器人异常时要写日志

### 6.2 可迁移性

- 路径、密钥、端口全部通过 `.env` 配置
- 不把本地绝对路径写死在代码中
- SQLite 文件路径可配置
- Obsidian vault 路径可配置
- 后续可迁移到云服务器

### 6.3 可维护性

- 功能按模块拆分
- 飞书、AI、账本、待办、提醒、知识库分别封装
- 数据库 schema 可迁移
- prompt 和 schema 可版本化

### 6.4 可观察性

- 记录请求 ID
- 记录消息处理状态
- 记录提醒发送状态
- 记录错误日志
- 保留最小必要调试信息

## 7. MVP 不做事项

第一版明确不做：

- 微信入口
- 企业微信入口
- Telegram 入口
- Web 前端
- 手机 App
- 多用户
- 群聊
- 多 agent 协作
- 项目管理系统
- 子任务和看板
- 复杂财务系统
- 账户余额管理
- 自动重构整个 Obsidian vault
- 自动删除或移动已有笔记
- 语音输入
- 本地大模型私有化

## 8. 验收标准

MVP 完成需满足：

- 飞书机器人可以私聊收发消息
- 只响应白名单用户
- 30 条真实输入至少 27 条处理正确
- 账本流水能写入 SQLite
- 账本能导出 Excel
- 待办能创建、查询、完成
- 一次性提醒能到点触发
- 简单重复提醒能工作
- 7 天真实试用期间无提醒漏发
- 文本能总结为 Obsidian Markdown
- 链接能总结为 Obsidian Markdown
- 高敏信息不会发送给 LLM
- 错误有日志可查

## 9. 主要风险

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 旧笔记本休眠 | 提醒失败 | 关闭休眠、接电源、开机自启 |
| 内网穿透不稳定 | 飞书 webhook 失效 | 使用 cloudflared，后续迁云 |
| 飞书配置复杂 | Day 1 受阻 | Day 1 只验收收发消息 |
| AI 误判意图 | 记错数据 | JSON schema、低置信度反问 |
| 敏感信息泄露 | 隐私风险 | LLM 调用前本地敏感检测 |
| Obsidian 分类混乱 | 知识库质量下降 | PARA 受控写入，不确定反问 |
| 提醒漏发 | 核心体验失败 | 状态机、重试、日志、备用提醒 |
